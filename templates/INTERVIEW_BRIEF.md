# Embedded QA Interview Brief

## 90-second project story

Build your answer as follows:

1. **Product** — what kind of embedded/IoT system it is.
2. **Risk** — which 2-3 risks were the most critical.
3. **Strategy** — how you decided to test them.
4. **Evidence** — what evidence you collected.
5. **Finding** — what you discovered.
6. **Decision** — how it affected the release/quality decision.

## Self-Assessment Questions

- Why did you automate these specific tests?
- What did you not test in Wokwi, and why?
- How did you prove that a reset equals successful recovery?
- How did you distinguish a firmware bug from a test/environment issue?
- Which test would you run in regression after a network stack change?
- What should be done if all tests PASS but the evidence is incomplete?
- Which residual risk would you accept, and which would you not?
- What would you verify on real hardware before production?
